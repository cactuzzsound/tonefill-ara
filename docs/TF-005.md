# TF-005 — Make the plugin a real ARA effect (execution checklist)

Goal of TF-005: the host **recognizes the plugin as an ARA effect**, creates our document
controller, and **pulls audio through our playback renderer** for the region. Reading clean
ambience (TF-102) and archiving the model (TF-801) are NOT in this task — the playback renderer
may return silence or whatever the render cache holds. This task is "ARA plumbing is alive".

Reference: mirror `JUCE/examples/Plugins/ARAPluginDemo.h`. It is the canonical, compiling
example of every class below. Do not invent signatures — copy the override shapes from there
for your pinned JUCE version (7.0.12), then adapt the bodies to our types.

Prerequisite: ARA SDK pinned and `TONEFILL_ARA_AVAILABLE == 1` (see docs/SETUP.md). Everything
below lives inside `#if TONEFILL_ARA_AVAILABLE` so the plain-insert build stays green.

## Subtasks (file by file)

### TF-005a — DocumentController binding  ·  `src/plugin/ara/DocumentController.{h,cpp}`
- Replace the placeholder class with a subclass of
  `juce::ARADocumentControllerSpecialisation`.
- Override the factory hooks ARAPluginDemo overrides, at minimum:
  - create-playback-renderer hook → return our `ARAPlaybackRenderer` subclass (TF-005c).
  - create-editor-renderer hook → return our editor renderer **or omit** (V1.1).
- Keep `CapabilityProfile capabilities_` and populate the cheap, always-knowable fields here
  (araActive = true; canRequestRender per host) so `ARAIntegrationFacade::detectCapabilities()`
  (TF-101) can read it.
- Do NOT implement archive store/restore yet — that's TF-801.
- Reference: the `...DocumentControllerSpecialisation` class in ARAPluginDemo.
- Acceptance: host creates the controller without error (log a line in its ctor to confirm).

### TF-005b — Export the ARA factory  ·  `src/plugin/ara/DocumentController.cpp`
- Export the ARA factory the way ARAPluginDemo does. JUCE provides a templated factory creator
  on the specialisation; the exact call/macro is version-specific — copy it verbatim from the
  demo for JUCE 7.0.12. This is what `IS_ARA_EFFECT TRUE` (already set in CMake) links against.
- Acceptance: `pluginval` / host scan tags the plugin as ARA-capable; the factory is found.

### TF-005c — PlaybackRenderer  ·  NEW `src/plugin/ara/PlaybackRenderer.{h,cpp}`
- Subclass `juce::ARAPlaybackRenderer`.
- Override the ARA renderer lifecycle (prepare / process / release) — copy the override set
  from ARAPluginDemo's playback renderer.
- Body for TF-005: write **silence** (or, if a fill is cached, the cached buffer) into the
  output for the requested sample range. The real model-driven fill arrives once
  `RenderManager` output is wired in a later task; keep the seam obvious.
- Threading: the process callback is the AUDIO/RENDER thread — lock-free read of an immutable
  buffer only (same rule as `processBlock`); no allocation, no analysis.
- Add the file to `PLUGIN_ARA_SOURCES` in `src/plugin/CMakeLists.txt`.
- Acceptance: host playback/bounce over the region pulls from this renderer (confirm via a
  one-time debug counter), output is silence without xruns.

### TF-005d — Processor ARA extension  ·  `src/plugin/PluginProcessor.{h,cpp}`
- At the documented "TF-005 insertion point", add the second base under the guard:
  `class PluginProcessor : public juce::AudioProcessor, public juce::AudioProcessorARAExtension`
  (wrap the `, public ...` in `#if TONEFILL_ARA_AVAILABLE`).
- In `processBlock`, at the existing `#if TONEFILL_ARA_AVAILABLE` seam: if bound to ARA, use

- Nothing else in the processor changes; `ARAIntegrationFacade` and `RenderManager` stay as-is.
- Acceptance: loads in an ARA host AND as a plain insert (no SDK build still compiles).

### TF-005f — Build wiring  ·  `src/plugin/CMakeLists.txt`

## processBlock routing (the one logic decision)

```
processBlock(buffer):
#if TONEFILL_ARA_AVAILABLE
    if (isBoundToARA() && araPlaybackHandled(buffer))   // JUCE helper renders ARA regions
        return;                                          // host pulled fill via PlaybackRenderer
#endif
    // not ARA-bound (plain insert) OR ARA did not cover this block:
    insertOrPreviewPath(buffer);                         // passthrough / cached preview
```
The exact `araPlaybackHandled(...)` helper name is in ARAPluginDemo — use that, don't invent.

## TF-005 Definition of Done
- ARA build compiles; non-ARA build still compiles (both modes green).
- Plugin scans as ARA-capable in `pluginval` and loads in ≥1 ARA host.
- Host creates our document controller (logged) and pulls audio through our
  `ARAPlaybackRenderer` (logged), output silence, no xruns / no crashes.
- Loads and passes audio as a plain insert when built without the SDK.
- `detectCapabilities()` reports `araActive = true` under ARA; fallback UX otherwise.

Order: TF-005a → TF-005b (factory) → TF-005c (renderer) → TF-005d (processor) →
TF-005e (capabilities) → TF-005f (build). a+b make it ARA-recognized; c+d make audio flow.
